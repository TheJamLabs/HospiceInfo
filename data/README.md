# Data provenance

Every file in [`data-raw/`](../data-raw/) and [`public/data/`](../public/data/)
with its source, fetch date, and how it is used. All data is committed to the
repository so the map is reproducible offline (only OSM **map tiles** are
fetched at runtime). Domain vocabulary used throughout: [`GLOSSARY.md`](../GLOSSARY.md).

## Current state (post-batch, 2026-10-16)

The committed `public/data/` is the **post-batch snapshot**: 8,364 of the
8,373 in-scope postcodes resolved (two full passes of
`scripts/geocode-postcodes.mjs` at 1 req/s, with 429/503 backoff and
outcode fallback). 9,552 practices are assigned; 12 sit in `hospiceId: null`
because their postcodes have **no OSM/Nominatim coverage at unit or outcode
level** (documented source gap, not a script bug):
`BT13 1AD, BT13 3BW, BT42 1GP, BT42 1NW, BT42 2PB, BT42 3JU, BT42 4JA,
BT63 6JS, BT79 0NR`. 138 charity shops, of which **21 sit outside their own
catchment** in this snapshot (recomputed on every build). Wales and
Northern Ireland show 0 hospices and Scotland 0 practices until the three
human fetches below land.

The tessellation also requires `data-raw/uk-land.json` (the committed OSM
land boundary, ADR-0006), which **is present** (fetched 2026-10-23;
SHA-256 and counts in the raw-inputs table above). The committed
`public/data/` has been rebuilt against it: catchment cells are now clipped
to the actual coastline, and `node scripts/validate-tessellation.mjs`
passes (cell polygons stay in-box, in-mask, and tile at shared
boundaries). Note that `build-data.mjs` and
`validate-tessellation.mjs` fail fast if the file is ever missing again
(no box-only fallback, no synthetic coastline). Both scripts consume the
raw mask via `scripts/land-mask.mjs`, which applies a deterministic
Douglas–Peucker simplification (tol 0.001°) **in memory** before any
clipping — the raw file stays untouched, so its SHA-256 remains the
provenance anchor and repeated `npm run build-data` runs produce
byte-identical `public/data/` output.

## Human fetch procedures (run on a machine with full DNS)

1. **RQIA register (Northern Ireland hospices)** — `data-raw/rqia-regulated-services-2026-06.xlsx`
   Open `https://publicregulation.gov.uk` in a browser and use the register's
   **data download / "All Registered Services"** export (the 08/06/2026 file
   named by research). Save it to
   `C:\Users\james\source\repos\HospiceInfo\data-raw\rqia-regulated-services-2026-06.xlsx`,
   then pin the exact as-of date from the file in this table (currently:
   **pending human fetch**). Re-run:
   `node scripts/extract-hospices-ni.mjs` → `node scripts/merge-hospices.mjs`
   → `node scripts/geocode-postcodes.mjs` → `npm run build-data`
   → `node scripts/validate-tessellation.mjs` → `npm run build`.
2. **Wales DataMap layers (Welsh GP practices)** — `data-raw/gp-practices-wales-{main,branch}-2026-10.{csv,geojson}`
   Open `https://data.wales` and search the catalog for the layers
   `geonode:gpmainsites_ogl` (main sites) and `geonode:gpbranchsites_ogl`
   (branch sites), OGL v3.0. From each dataset's download tab export the
   layer (CSV preferred; GeoJSON accepted) and save as
   `…\data-raw\gp-practices-wales-main-2026-10.csv` and
   `…\data-raw\gp-practices-wales-branch-2026-10.csv` (rename `.geojson` if
   that is the exported format). Re-run
   `node scripts/extract-gp-practices-wales.mjs` → geocoder → build chain as
   above.
3. **NHS Scotland GIS layer (Scottish GP practices)** — `data-raw/gp-practices-scotland-2026-10.geojson`
   The data.gov.uk CKAN dataset `gp-practices-scotland`
   (id `16f795a0-e87f-4ce2-a910-eeb7f9944632`) registers only portal links —
   no direct file. Open the Spatial Hub layer page
   (`https://data.spatialhub.scot/dataset/gp_practices-is`) in a browser and
   download the GP practices layer as GeoJSON to
   `…\data-raw\gp-practices-scotland-2026-10.geojson`. Re-run
   `node scripts/extract-gp-practices-sc.mjs` → geocoder → build chain as
   above.
4. **OSM land boundary (UK-wide catchment clipping, ADR-0006)** — `data-raw/uk-land.json` **— DONE 2026-10-23**
   On a machine with a normal network run `node scripts/fetch-uk-land.mjs`
   → commit `data-raw/uk-land.json` → record its SHA-256 and polygon count
   in the `uk-land.json` provenance row above → re-run `npm run build-data`
   (twice — outputs must be byte-identical) →
   `node scripts/validate-tessellation.mjs` → `npm run build`.
   The fetch box must stay wider west than the ADR-0001 map box (−9.5) so
   the Irish Sea / English Channel coastline loops close inside the query;
   the build and validator clip back to the map box, so out-of-box land
   (e.g. west of −9.5) never reaches the app (see ADR-0006).

## First-run header discovery (ADR-0003)

Every extract script logs the source header verbatim on its first successful
run against an unverified extract and then uses named, case-insensitive
column access: CQC 15 columns (header on line 5 after the 4 preamble lines),
Care Inspectorate Scotland 109 columns, NI reference file
`PracNo,PracticeName,Address1..3,Postcode,LCG,…`. The RQIA and Wales
columns are pinned the same way when those fetches land.

## Caveats

- The CQC directory is a snapshot (data date 14 Oct 2026) and the Care
  Inspectorate file is a 31 Aug 2026 extract; practice addresses/postcodes
  drift slowly.
- Geocoding is by **postcode unit centroid** (OSM), so a practice may sit a
  short distance from its dot.
- The map shows where *practices* are, not who is *served*: real referral
  depends on the patient's location.
- The crisp shared boundaries are a **Voronoi tessellation derived from
  practice and hospice-site locations** (single nearest-hospice rule); the
  real service-area switch between two hospices is fuzzier than the drawn
  line. The 20 curated catchments keep their hand-verified identities, but
  their drawn area is also tessellated.
- The `outsideCatchment` flag on shops is a geometry test (point inside the
  shop's own tessellated cell). A shop can be well within its hospice's real
  service area and still be flagged if it sits across the tessellated
  boundary, and vice versa. Treat it as an indicator of sites that *could*
  be over-reaching fundraising, not a judgement of it.
- Placeholder files (`[]`) remain until the corresponding human fetch lands;
  they are expected and do not break the build (Wales-style zero-set
  tolerance).
